# Участие в разработке

[← README](README.md)

Проект небольшой и находится на стадии интеграционной проверки. Особенно полезны воспроизводимые сообщения о несовпадении подписей меню, применении настроек и распознавании результата.

## Сообщить об ошибке

Создайте [Issue](https://github.com/huksleva/wukong-benchmark-automation/issues/new/choose). Укажите версию Windows/.NET, Steam build Benchmark Tool, команду, шаги и ожидаемый результат. При необходимости приложите отдельный диагностический кадр и очищенный фрагмент журнала. Не загружайте целую папку `results/`: резервные INI и манифест содержат локальные данные.

Уязвимости обсуждаются через [приватный канал](SECURITY.md), а не в публичных Issues.

## Предложить изменение

1. Создайте ветку от актуального `main`.
2. Ограничьте изменение одной задачей. Если меняется поведение, обновите соответствующую документацию.
3. Выполните Release-сборку и `dotnet run --project tests/Wukong.Tests -c Release`.
4. Для изменения парсера добавьте содержательную OCR-фикстуру. Для адаптера меню укажите, на какой сборке проверена работа.
5. В Pull Request опишите проблему, результат и выполненную проверку. Отдельно отметьте, запускался ли настоящий Benchmark Tool.

Не включайте локальные конфигурации, результаты с личными данными, бинарные файлы игры и зависимости сборки. Следуйте [правилам общения](CODE_OF_CONDUCT.md). Изменения принимаются на условиях существующей [лицензии MIT](LICENSE).
