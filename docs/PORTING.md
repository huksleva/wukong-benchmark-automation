# Полный перенос и дальнейшее развитие

[← README](../README.md)

## Текущее состояние

- **Реально проверено:** два игровых прохода на Windows; нативный Reports на Linux x64/ARM64 и macOS Intel/Apple Silicon.
- **Подготовлено в исходниках:** `Wukong.Engine` на обычном `net8.0`, без Win32, WinForms и Windows OCR. Windows-приложение использует его через оконный и OCR-адаптеры. В CI общий сценарий проверяется с тестовыми адаптерами.
- **Ещё не реализовано:** Linux/macOS запуск Benchmark Tool, OCR изображений и оконные адаптеры для этих ОС.

Полноценный Linux-порт возможен. Смена Runtime Identifier сама по себе не заменяет оконные API и не обеспечивает совместимость Windows-бенчмарка.

## Последовательность Linux-переноса

1. **Зафиксировать целевую среду.** Дистрибутив, x64/ARM64, GPU/драйвер, X11/Wayland, версия Steam/Proton и успешный ручной запуск бесплатного Benchmark Tool. Для первого этапа X11 проще: [xdotool](https://github.com/jordansissel/xdotool) предоставляет оконное управление и ввод для X11; его README прямо указывает ограничения Wayland. Поддержку Wayland следует проектировать отдельно.
2. **Реализовать адаптеры.** `IBenchmarkWindow` с координатами клиентской области, фокусом, снимками и вводом; `IBenchmarkOcr` с локальным [Tesseract](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html), масштабированием, вырезанием областей и геометрией слов. Дополнительно нужны обнаружение Linux Steam, библиотеки игры/Proton, аппаратная диагностика и корректное закрытие своих процессов.
3. **Проверить игровые проходы на хосте.** Одинаковые профили, повторное считывание настроек, две стабильные выдачи результата, исходные кадры/OCR, настоящий CPU/GPU отчёт и побайтовое восстановление INI. Версию Proton и графического слоя сохранять в условиях замера; результаты через Proton не считать автоматически идентичными Windows.

## macOS

Нужны версия macOS, Intel/Apple Silicon и подтверждённый способ открыть сам бенчмарк. [Game Porting Toolkit](https://developer.apple.com/games/game-porting-toolkit/) предназначен в том числе для оценки Windows-игр на Apple Silicon, но наличие инструмента не доказывает поддержку нашего бенчмарка. Оконный ввод, снимки, разрешения системы и графическая совместимость здесь проверяются отдельно. Сейчас в macOS-релизе доступен только Reports.

## Что сильнее приблизит проект к production

| Приоритет | Улучшение | Критерий готовности |
|---|---|---|
| 1 | Восстановление после аварийного завершения | При следующем старте обнаруживается незавершённый запуск; исходные INI восстанавливаются из проверенного манифеста до нового теста |
| 1 | Проверки на разных компьютерах | Настоящие проходы на нескольких AMD/NVIDIA/Intel GPU, Windows 10/11, языках, масштабах экрана и мониторах; опубликованная матрица поддержки |
| 1 | Контроль вмешательства | Потеря фокуса/изменение окна фиксируются; результат получает предупреждение или признаётся недействительным по документированному правилу |
| 2 | Надёжнее замеры | Прогрев, серия повторов, медиана/разброс FPS; версия игры, драйвера и совместимости в отчёте; при необходимости измерение загрузки компонентов |
| 2 | Подпись дистрибутивов | Подпись Windows, Developer ID и нотарификация Mac; проверяемая привязка релизных файлов к исходному коммиту |
| 2 | Интерфейс и диагностика | Видимый прогресс, отмена, понятная подготовка компонентов, диагностический пакет без случайного раскрытия локальных путей/данных |
| 3 | История и сравнение | Версионированная схема JSON, сравнение одинаковых условий и экспорт таблиц; несовместимые протоколы не смешиваются |

Это план работ, а не перечень уже реализованных возможностей. Полноценная кроссплатформенная игровая автоматизация требует реальных проверок на целевых ноутбуках; зелёный CI с тестовыми адаптерами подтверждает только программную логику.
